# Screen Spec — Home Landing

**Route**: `/`

**Active prototype source**: `ui-ux-v2-flagship`

**Product mode**: Acquisition

**Primary action**: `Open Rooms`

## 1. Goal

The home page must convert a first-time visitor.

It must answer, within one fast scan:

1. what ArbiGameFi is
2. why it is trustworthy
3. where to start playing

## 2. First Fold

The first fold contains:

1. minimal landing header
2. value proposition
3. primary CTA
4. secondary CTA
5. light proof ribbon
6. one hero visual anchor

It does not contain:

- operational telemetry
- heavy room detail
- dense metrics cards
- full room UI

## 3. Page Order

1. hero
2. proof ribbon
3. featured rooms rail
4. how it works
5. why trust it
6. live proof
7. final CTA

## 4. Hero Rules

- hero copy is short and product-facing
- one dominant CTA only
- secondary CTA remains clearly subordinate
- visual anchor supports memory and brand, not explanation

## 5. Featured Rooms Rules

- this section is the real room-entry surface
- use a horizontal room-entry rail
- cards must feel like playable room entries, not generic product cards
- one-line room promise only
- minimal facts only

## 6. Copy Rules

Hero copy should emphasize:

- wallet-native play
- non-custodial entry
- readable settlement
- visible room facts

Hero copy must avoid:

- release digest
- indexer
- manifest
- low-level protocol language

## 7. Visual Rules

- acquisition tone is editorial and premium
- proof is light, not dashboard-like
- sections must not all use the same visual rhythm
- glow supports hierarchy and never becomes the hierarchy

## 8. Mobile

- hero stacks vertically
- proof ribbon compresses into compact tiles or short rows
- featured rooms become a vertical stack or swipeable rail
- CTA remains visible without long scroll
