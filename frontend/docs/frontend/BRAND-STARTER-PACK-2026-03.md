## 1. Purpose

This document defines the minimum public brand system that must exist before final UI design or frontend implementation continues.

It is not a full marketing brand book.
It is a practical starter pack for:

- logo design
- landing page design
- room UI design
- copy and CTA design
- social and app icon preparation

Without this pack, screens will continue to drift between:

- protocol naming
- casino naming
- generic crypto visual language

---

## 2. Brand Model

### 2.1 Public brand

`ArbiGameFi`

This is the only public product name that should lead the interface, landing page, social cards, and wallet-facing app identity.

### 2.2 Internal architecture term

`SSOT`

This remains an internal architecture principle:

- single source of truth
- release-driven protocol identity
- auditable frontend behavior

It must not appear as the product brand in the main UI.

### 2.3 Working category

ArbiGameFi is best described as:

- on-chain game rooms
- wallet-native gaming
- auditable game settlement

Avoid positioning it as:

- a memecoin casino
- a generic GameFi portal
- a DeFi dashboard with mini-games

---

## 3. Brand Thesis

### 3.1 Core statement

ArbiGameFi is a premium on-chain game room product where players place wallet-native bets and verify outcomes through transparent settlement rails.

### 3.2 Brand promise

The product should communicate three promises at once:

1. playing is immediate
2. custody stays with the user until signature
3. settlement is inspectable

### 3.3 Emotional posture

The brand should feel:

- sharp
- premium
- controlled
- credible
- playable

The brand should not feel:

- loud
- childish
- overly meme-driven
- over-technical on first contact
- visually improvised

---

## 4. Audience Lens

### 4.1 Primary audience

Crypto-native players who already understand wallets and want a cleaner, more trustworthy on-chain gaming surface.

### 4.2 Secondary audience

LPs, partners, and serious users who care about:

- protocol credibility
- transparent liabilities
- release identity
- auditable actions

### 4.3 Implication for design

The brand cannot optimize only for casino excitement.
It must combine:

- room energy for players
- institutional clarity for trust-sensitive users

## 5. Naming Rules

### 5.1 Product naming

Use:

- `ArbiGameFi`
- `ArbiGameFi Rooms`
- `ArbiGameFi Liquidity`

Do not use:

- `SSOT v2`
- `SSOT Frontend`
- `SSOT Games`
- `Arbi Game Fi`

### 5.2 Feature naming

Prefer:

- `Rooms`
- `Bets`
- `Liquidity`
- `Account`
- `Claims`
- `Referral`
- `Ops`

Avoid over-branding every feature.

### 5.3 Game naming

Use plain game names:

- `Dice`
- `Coin Toss`
- `Roulette`
- `Keno`

Do not invent branded mini-titles unless a future product strategy requires it.

## 6. Logo System Requirements

### 6.1 Required deliverables

The first logo pass must produce:

1. primary wordmark
2. icon mark
3. horizontal lockup
4. dark-background version
5. single-color version
6. favicon / app icon version
7. social avatar version

### 6.2 Recommended direction

Primary design direction:

- a clean `AG` monogram
- with one controlled orbital or table-rail gesture
- suggesting motion, edge, and precision

This direction fits the product better than:

- literal dice icons
- cartoon mascots
- full roulette wheel illustrations
- generic token logos

### 6.3 What the logo should suggest

The logo should imply:

- motion
- outcome
- precision
- premium gaming
- controlled infrastructure

### 6.4 What the logo must avoid

Do not use:

- fake casino clip-art
- gradients as the logo itself
- excessive glow
- skulls, flames, crowns, or meme mascots
- over-detailed linework that breaks at small sizes

### 6.5 Clearspace and sizing rules

The formal logo pack should define:

- minimum clearspace based on icon height
- minimum wordmark size for web
- minimum app icon size
- favicon fallback behavior

For now, design assuming the icon mark must still read at:

- `16x16`
- `32x32`
- `64x64`

## 7. Color Baseline

This is a starter palette role system, not the final token sheet.

### 7.1 Core roles

- `Night`: primary background
- `Graphite`: elevated surface
- `Plum`: premium room accent
- `Crimson`: active game energy accent
- `Mint`: success / balance / positive state
- `Amber`: warning / pending state
- `Ice`: high-contrast text and lines

### 7.2 Directional starter values

- `Night`: `#090B14`
- `Graphite`: `#141827`
- `Plum`: `#4B2D8F`
- `Crimson`: `#C93B63`
- `Mint`: `#52D4A6`
- `Amber`: `#D6A24A`
- `Ice`: `#F3F6FF`

### 7.3 Usage rule

Gameplay routes can use richer accent contrast.
Trust routes should keep stronger neutrality and use accent sparingly.

Do not turn every surface purple.

---

## 8. Typography Baseline

### 8.1 System split

Use a two-role typography system:

- display type for landing and room identity
- UI type for controls, tables, and metrics

### 8.2 Directional recommendation

Recommended exploration:

- display: `Space Grotesk` or `Sora`
- UI/body: `Inter` or `IBM Plex Sans`

The final choice should optimize for:

- strong uppercase room labels
- good numeric legibility
- dense table readability

### 8.3 Numeric rule

Metrics, balances, payout previews, and ticket values should use:

- tabular numerals where possible
- tighter vertical rhythm
- lower decorative styling than headlines

## 10. Brand Voice Summary

ArbiGameFi should speak like a premium product, not a hype campaign.

Voice traits:

- direct
- assured
- clear
- controlled
- modern

Avoid:

- exaggerated promises
- trading-floor slang
- forced web3 jargon
- casino shouting language

---

## 11. Immediate Design Implications

This pack freezes several decisions for upcoming Figma work:

1. `ArbiGameFi` is the only public brand name.
2. The first logo pass should prioritize an `AG` monogram plus wordmark system.
3. The landing page should feel editorial and premium, not like a dashboard.
4. Game rooms should feel like active tables with disciplined chrome.
5. Trust routes should look calmer and more financial than gameplay routes.
