## 对比结论

轮数比较使用收据压缩之前的同一份源码、真实 Base Sepolia wrapper/USDC fork，
8 个游戏各跑一个固定输入的 25 轮和 50 轮完整受限回调。历史包含 1,023 笔已全部退出的旧存款、
1,024 笔后入存款，九条奖励、七个收款人，玩家拒付后记为应付款。

- **25 轮：8/8 首次完成。** 本组最高观测值为 Keno 的 2,340,221 gas。
- **50 轮：6/8 首次完成。** Keno、Plinko 需要原 seed 重试。
- 所有 16 个输入的资金与终态断言通过，但重试成功不计首次完成。

合约统一硬上限为 **25 轮**，每个游戏允许登记更低的合格上限。
现有游戏登记接口已支持每个游戏的最大轮数，无需为这个选择重写玩法或引入第二套 provider。
GameHub 在入款和 VRF 请求前直接校验每轮金额及轮数；Bank 配置 `minBetAmount`，
USDC 部署模板为 10,000 原始单位。SDK 和页面读取同一链上值，页面不再将一个总额除以轮数。
旧总额配置接口已替换，没有保留兼容入口；未广播部署。

## 仍须说清的边界

减少轮数降低游戏计算成本，不消除历史相关的树记账成本。25 轮通过这组样本，
不能证明任意合法参数、seed 与完整树生命周期首次回调都能完成。
先前极深树合成见证单独记账已超过 provider 预算；它不是现实执行万亿次存款或现实攻击的证据。

用户此前提出的“所有允许状态首次完成”仍未被证明；此次轮数建议不能被当作该要求已经达成。
