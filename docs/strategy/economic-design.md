# Casino 经济设计与参数校准

项目尚未上线。2026-10-04 接受的目标是 **NFT 存款、固定 24 小时冷却、Azuro LiquidityTree 分配、双托管和回调内结算**，核心与消费者已实现并通过本地验证，发布准入尚未完成。唯一规范见 [SSOT v1.6](../constitution/SSOT.v1.6.md)、[ADR-0032](../adr/0032-fixed-lp-share-operator-funded-referrals.md) 和 [ADR-0034](../adr/0034-nft-liquidity-deposits.md)，改动顺序及原始代码身份见[实施计划](../design/lp-accounting-and-callback-implementation.md)。本文不把旧方案测试结果当作本方案已实现。

## 玩法分配保持不变

金额用资产最小单位，费率用 bps。投注接受时固定唯一 house edge、推荐关系与分配版本：

```text
s = 本金; f = 未使用本金退款; u = s-f
feeOnPayout = floor(payoutGross × houseEdgeBps / 10000)
payoutNet = payoutGross-feeOnPayout
E = floor(u × houseEdgeBps / 10000)
O = floor(E / 2)
LP 理论留存 = E-O
PF_new + XP_new <= O
```

LP 留存比例为常量 50%，整数余数向 LP 保留。推荐奖励来自运营预算 O，L0/L1/L2 比例合计不超过该笔流水 edge E 的 35%；缺失推荐人和分配尾差归协议。XP 的 accrued、locked、holdback 都是已计提债务，不能重复算作 LP 资本。

`feeOnPayout` 按毛派彩扣减，E 按已使用流水计算，不能混用。无派彩的输局也可能产生运营预算。SettlementRouter 从开仓记录独立限制 PF/XP，Bank 另外检查整笔终结成本。完整退款不产生运营分配。

有 LP 资本时，该留存通过终结净盈亏计入树；树为空时无人承接的正收益按下文规则作为单独的协议资本，而不是提高玩法抽成。公平毛赔付模型且忽略整数误差时，全体 LP 的理论期望约为流水 edge 的一半，不是单张 NFT 的保证回报，也不能推算承诺 APY。各 NFT 的存款范围、退出时间、后备分配和有限样本波动会改变实际结果。

## Bank 与 LiquidityVault 分开保管

Bank 在构造时创建不可变 LiquidityVault。Vault 保管 LP 本金、NFT 和原始树；Bank 保管玩家本金、PF/XP 与玩家应付款。资金归属和计算如下：

```text
B_B / B_V = Bank / Vault 实际代币余额
PF / XP / PP = 协议、推荐、玩家债务
P = 未结仓位原始本金之和
R = 未结仓位毛赔付准备金之和
L = LiquidityTree 根金额 = LP 资本 = SSOT NAV
K = Vault.lockedLiquidity = R-P
G = L+P = riskAssets
D_B = B_B-(P+PF+XP+PP)          未分配 Bank 多余余额
D_V = B_V-L                    未分配 Vault 多余余额
```

有效状态要求 `B_B>=P+PF+XP+PP`、`B_V>=L`、`R>=P`、`L>=K`，即 `G>=R`。总现金等于 `L+P+PF+XP+PP+D_B+D_V`。

直接向任一合约转币只增加未分配余额，不增加树、不增加下注容量，也不让下一位首存者取得它。首版只报告这种 surplus，不新增归集或分配入口。资产缺口、锁定不一致或权威读取不可用应明确报错并拒绝 LP 资金变动、新风险和可选出金，不能把错误显示成健康零净值。NFT 接口没有 ERC4626 的读接口承诺；不保留它的份额报价或兼容层。

首轮只支持标准 USDC：无转账税、无 rebase、失败转账不改变余额。新增存款、本金及跨托管记账都核对实际到账。发行方冻结仍可能阻止真实付款，不能靠账本消除。

## 每次存款一张 NFT

用户授权 Vault，并通过 Vault 的唯一 LP 存款入口实际入金。每次创建新叶子和新 NFT，资本立即生效，`withdrawAfter=现在+24小时`。24 小时是本项目固定常量，没有 setter；这是相对 Azuro 可调整期限的一项明确适配。

再次入金创建另一张 NFT，不追加到旧 NFT。赠送存款不会延长接收人已有 NFT 的冷却。NFT 转让携带原 ID、当前金额、分配范围与期限：未成熟的不能通过转让提前提现，已成熟的转让后也不重新等待。

只有 NFT 当前 owner 可以提款，资产只付 owner。approve/operator 虽不能直接代表 owner 取现金，却能转走 NFT，因此仍相当于授予资产控制权；前端不得要求授权 keeper。

提款按原树 `1e12=100%` 的比例执行，检查成熟时间、Bank 的 LP 状态及资金条件：

```text
本次实际提款 <= L_before-K
```

不再对 LP 提款叠加比例 withdrawalBuffer。部分提款成功后，该 NFT 剩余部分重新锁 24 小时；全提烧 NFT。零比例和金额取整为零的部分提款拒绝；已经成熟、余额为零的 NFT 可用 100% 操作清理。转账或额度检查失败，提款、销毁和重置时间全部回滚。

K 为正时，准备金本身禁止把池子提空；K 为零时允许所有 NFT 退出，即使仍有零净风险的旧仓位。不再添加“最后一份额不得退出”的规则。提前退出的部分不再分享后续入账盈亏，没有旧风险回收权。

## 下注仍用已确认的风险公式

开仓必须有正 L，并由 Bank 固定当时的 `lastDepositId`，不让调用方任意选择受损或获益的存款范围。以开仓作为赌场的快照时点是本项目决定，不能声称已验证 Azuro 不公开的 V3 Core 也使用同一时点。

玩家本金 s 进入 Bank，LP 的 L 不变；总准备金 r 必须不少于 s，新增锁定仅为 r-s：

```text
P_after=P+s; R_after=R+r
G_after=L+P_after
R_after + floor(G_after × riskReserveBps / 10000) <= G_after
K_after=K+(r-s)=R_after-P_after
```

新部署默认 `riskReserveBps=6000`，按收到本次本金后的 G 保留 60%；SDK 和游戏界面读取实际配置，
与合约使用同一个 G、R 和整数规则。PF/XP 领取缓冲独立默认 1000 bps，不是 LP 提款比例。每池仍最多 128 个未结仓位，终结才释放名额。LP 提款不触发计划性停注，但资本减少后可承保金额也必须立即降低。

另设原树的数值准入上限 `G<=2^108-1`，存款和新增 stake 都检查。它保证原算法中乘积再乘 `1e12` 不超 uint256；仅限制 L 不够，因为全部未结本金可能随后变为 LP 盈利。这个极高的数据上限不是更换业务风险比例。延迟传播的存储节点可能大于当前根，仍需独立验证固定上限、uint128 转换及叶子/更新编号边界。

## 结算与树的分配

终结成本 `C=payoutNet+refund+PF_new+XP_new` 必须不超过 r。Bank/Vault 用一个原子终结流程释放 k=r-s、去除整笔 P/R、更新树并完成必要资金划转：

| 结果              | 托管与分配                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------- |
| C>s，LP 亏损      | 用原树的 push 与 lazy 分配在 allocationLeaf 范围内扣除 C-s，Vault 向 Bank 转入 C-s，保证玩家和费用有资金 |
| C<s，且结算前 L>0 | Bank 向 Vault 转入 s-C，同样在 allocationLeaf 范围内增值；k=0 时仍走原 `_addLimit`；NFT 冷却不重置 |
| C=s               | 仅释放准备金并终结，无净盈亏划转；完整退款属于此类                                          |
| C<s，但结算前 L=0 | 不调用空树加值；s-C 留在 Bank 并记独立 PF 协议资本，单独事件、不计玩法费用                  |

正常树分支满足 `ΔL=s-C`、`ΔG=-C`。空树正收益分支保持 L=0，额外 PF 增加 s-C，因而 `ΔG=-s`，不能沿用正常 LP 盈利公式。该分支防止空树遗留价值被下一位首存者拿走，没有新增协议风险账户。

复用区间树的整数分配，不重写比例算法。Vault 按每仓原始最大 LP 亏损 k=r-s 选择 allocationLeaf：当前 cutoff 前缀资本 >=k 时，利润和亏损都用 cutoff；否则都用最后已用叶子，即当前全树。k=0 保留 cutoff 和空前缀回退，空根利润仍归协议资本。这消除非空薄前缀保留全部利润、亏损却外溢的不对称；收益预期和风险均随分配范围变化，并非只转移波动。范围在每仓结算时判断，多仓顺序可能改变 NFT 余额。后加入者不能被承诺“绝不承担旧仓损失”，也不保留已退出者权利。

玩家付款失败可记 PP，整笔合法终结继续；之后领 PP 不再次扣树或释放 K。Bank/Vault 之间真实划转失败则整体回滚，不能用玩家欠款假装树已收到资金。协议和奖励向外领取只减少 Bank 余额与对应债务，仍受既有 PF/XP 可选出金规则；其 withdrawalBuffer 不限制 NFT 提款。向 Bank 自身付款只成为明确的未分配余额，不自动归 LP。

## 回调、信息窗口与放行

正常随机数回调同笔结算；失败保存原结果，公开或 keeper 重试同一个 seed。Vault 通过 Bank 读取 canonical VRFHub 已保存未记账的数量及 pause/busy/账目状态。任何结果已经保存但未正确入账，包括失败在 GameHub 收到之前，都禁止 LP 入金和提款；Bank-only 结算入口不走这个 LP gate，否则无法清除故障。

一小时仍表示没有收到随机数时首次允许申请退款，不是退款机会到期。已经保存 seed 的仓位不能超时作废，也不能因 gas、任意回滚或无效结果元组而改成退款。

NFT 和 24 小时冷却并未消除成熟 LP 的有信息退出：自由资本允许时，成熟 NFT 可以在亏损入账前退出，损失由留存资金承担；空或不足 prefix 的 fallback 也可能让后入资金取得旧利润或承担旧损失。用户已明确选择保留既定规则，接受并公开披露该风险。条件退出与利润排序的本地见证和接受记录见 [ADR-0034](../adr/0034-nft-liquidity-deposits.md#pre-inclusion-ordering-owner-decision-2026-10-04)；见证不证明真实 VRF 可提前预测，风险接受也不等于排序优势已修复。

## 成本、验证和展示

| 成本                               | 责任                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------- |
| Vault 授权、NFT 入金/提款/转让 gas | 交易发起人支付，报价单列                                                |
| 正常 VRF 完整回调                  | 玩家按真实 wrapper 报价预付；包括树和跨托管结算，实际费用与返还分别记账 |
| 异常重试、合格退款、玩家债务付款   | 运营方为 keeper 提供原生资产；用户也可主动触发                          |
| RPC、索引、监控、维护              | 运营预算承担，不重复扣 LP 或奖励权益                                    |

PF 以池资产计价，回调/keeper 用原生资产；已计提不等于可以立即提走。必须测量完整 wrapper→VRFHub→GameHub→Router→Bank→Vault/tree，包含最多 40 层树遍历、全树后备、双向资金划转、最多轮数和奖励、失败付款及终态确认。原 ERC20 模型和单独 finalize 的 gas 结果不是本方案证据。

Earn 按 NFT 展示当前金额、可提时间、流动性约束和部分提款重锁。索引跟踪 NFT 所有权、真实现金、赠送及重组；不把树内增值提前当作实际到账。游戏界面必须在提款收据之后刷新同区块资本和最大注额，不能继续显示提款前池额。keeper 不持有 NFT 授权，不执行 LP 批次动作。
