# Casino 经济设计与参数校准

项目尚未上线。本文说明当前经济模型及上线前需要校准的成本和资本参数；唯一规范是 [SSOT v1.6](../constitution/SSOT.v1.6.md)、[ADR-0032](../adr/0032-fixed-lp-share-operator-funded-referrals.md) 、[ADR-0034](../adr/0034-async-lp-redemption-continuous-betting.md) 和 [ADR-0035](../adr/0035-recovery-rights-without-exit-blocking.md)。发布状态见[发布说明](../release/README.md)。本文不定义体育收入分配。

## 当前分配规则

金额使用资产最小单位，费率使用 bps。每笔投注接受时固定有效 edge、基础 edge、推荐关系与分配版本。

```text
S = 投注本金
Q = 未使用本金退款
U = S - Q
G = 规则毛派彩
F = floor(G × effectiveEdge / 10000)
N = G - F                      玩家净派彩
E = floor(U × effectiveEdge / 10000)
O = floor(E / 2)               运营预算
LP 留存 = E - O
PF_new + XP_new <= O
```

LP 的份额是合约常量 50%；整数余数使 `E - O` 向 LP 保留。DefaultReferralEngine 从运营预算分配玩家返水、推荐奖励和推广加价奖励，剩余计入协议费用。基础推荐比例合计不超过基础 edge 的 35%；缺失推荐人及推荐分配的舍入余数归协议。锁定、holdback 和已成熟奖励都属于 XP 债务，不能同时作为 LP 留存。

`F` 是玩家毛派彩的扣减，`E` 是按实际流水计算的理论 edge，两者不能混用。即使单局没有派彩，仍可产生 `O`。SettlementRouter 根据开仓记录独立限制新增 PF 与 XP 总额，Bank 继续检查预留和完整负债后的偿付能力。纯退款不产生运营分配。

仅计玩法本身、尚未扣除另行标识的虚拟资本残值和出入金时：

```text
Δ(活跃 NAV + 历史风险资本) = U - G + F - PF_new - XP_new
```

公平毛赔付模型下，忽略整数误差并足额计提运营预算时，LP 理论期望约为实际流水的有效 edge 的一半。它不是本金收益率：有限样本可能亏损，提前停止需要计算实际流水与结果的联合分布，不能用计划投入或假定周转次数推算 APY。

## 资本、负债与退出

```text
活跃 NAV = 实际资产余额 - PF - XP - exitPayable - playerPayableTotal - recoveryBacking
活跃 NAV >= activeReserved（仅当前期准备金）
totalReserved = activeReserved + 历史各期剩余准备金
```

预留是对 LP 资本用途的约束，不再从 NAV 扣一次。协议、奖励、已定价退出和玩家欠款都在建立债务时扣除 NAV；向外部接收人支付时，余额和债务等额减少。捐赠与向 Bank 自身领取需要另行归因。

存入和 mint 即时按活跃池带虚拟偏移的账面价执行，存入者参与当前期风险，不取得已隔离历史期的回收权。退出先排队，到实际激活时隔离当前期完整准备金，冻结所有当时持有人的历史权利，烧毁申请份额并定价可支取现金。此后新投注、新入金和下一期退出继续运行。

每个历史期按 ADR-0035 的整体冻结曲线计算累计回收，再按快照份额分配；不能直接按实际份额比例返还准备金，也不能逐笔舍入。旧期完成部分仓位后就能释放相应回收，不必等待该期全部终结。释放但尚未领取的回收仍排除在活跃 NAV 外。零钱包份额和全部 LP 退出不会清除历史权利。

虚拟资本回收、全退出的液态虚拟残值和最终历史分配尾差归协议资本，单独记录，不计入玩法 PF 或流水 edge。部分退出不把所有留存 LP 的液态残值提前扣走。现金账本必须记录实际回收付款；未来回收上限不是现金，也不是确定收益。

无法终结的旧仓只继续占用对应历史资金，不阻塞后来批次；若全部资金都承担未终结风险，可支取现金仍可能为零。不存在超时强制折价或把有效赢家改成退款的路径。玩法与资产仍须通过有效终结路径准入，体育有独立门槛。

## 成本承担

| 成本                                                | 支付与核算责任                                                      |
| --------------------------------------------------- | ------------------------------------------------------------------- |
| 授权、投注和用户主动恢复的 gas                      | 交易发起人支付，报价单列                                            |
| VRF 费用                                            | 玩家预付，实际 charged 与多付退款分别记录；退款 credit 不算协议收入 |
| 自动 finalize、退款、批次激活和代领玩家应付款的 gas | 运营方为 keeper 提供原生资产运行资金                                |
| RPC、索引、监控、支持与维护                         | 运营预算承担，不再次扣减已归属 LP 或推荐人的权益                    |
| LP 请求、取消和领取 gas                             | 发起交易的 LP 承担，计入个人现金成本                                |

PF 以池资产计价，keeper 主要消耗原生资产；已计提收入也不必然立即可领取。运营方需要独立的运行储备。任何费用补贴单独标明资金来源、额度和期限。

## 上线前校准

校准基础 edge、推荐版本、最小金额、回合上限、风险缓冲、批次周期和 capital limits 时，使用以下证据：

- 各玩法和停止参数的结果分布、最大赔付与实际整数计算；覆盖输、赢、部分退款、零额及尾部情景。
- 玩家实际 gas、VRF charged、等待与恢复成本；按资产、玩法和批量规模区分。
- keeper 正常及故障路径的实际 gas、失败重试和运行预算。回调预算与 finalize 预算分开验证。
- LP 的未结算敞口、连续损失、集中退出、暂停和无法终结头寸情景。
- 渠道的有效使用、回访、归因、领取成本及实际贡献；不将流水等同于利润。

若可接受的最小使用金额高于资本允许的风险上限，当前配置没有可用区间；应调整成本、范围或明确补贴，不能靠收益宣传弥补。LP 资金、经营收入、捐赠和用户欠款分别对账，现金流水记录真实 Deposit、Withdraw 与 RecoveryClaimed；请求、风险隔离和批次烧毁不算提款，向 Bank 自身领取作为捐赠单列。
