## 1. 项目命题

ArbiGameFi 建设一个钱包原生的单品牌 casino 与 sportsbook。娱乐体验是产品核心，可核对的规则、结算和资本约束构成信任基础。我们争取的不是“读完协议论文的人”，而是愿意使用这个产品、并能清楚理解支出与结果的人。

本阶段的商业假设是：已有 EVM 钱包和稳定币经验的一部分用户，会偏好无需平台托管账户预充值、费用清楚、支付可核对的娱乐产品。项目需要以使用体验、留存、资本质量和成本覆盖验证这一假设。公开源码、部署完成或测试通过都不构成市场验证。

品牌工作句：**用自己的钱包参与游戏，看清每一次投入与结算。** 它是内部叙事方向；实际页面承诺须与所用版本一致。投注资金进入合约，不应把钱包控制权说成资金永不离开钱包。

## 3. 产品如何获得选择理由

玩家首先需要有吸引力且容易理解的玩法、顺畅的使用、可接受的总成本和可靠支付。可验证性支持信任，并不能自动带来兴趣或再次使用。

我们要组合交付三件事：

1. **娱乐与使用体验：**既有玩法统一而有各自表现，移动钱包入口清楚，签名和等待不打断用户理解，结果清楚且可复查。
2. **资金与费用透明：**玩家看到总支出和净派彩；LP 看到自己承保的池、真实负债与退出能力；伙伴看到奖励来源和结算。
3. **稳定服务：**正常流程自动完成，异常时能找回进度和有效权利；用户不用承担工程排障工作。

这是一项需要验证的组合优势。2026-09-26 查阅的 [Stake 官方说明](https://stake.com/provably-fair/overview)和 [Shuffle 官方说明](https://shuffle.com/info/provably-fair)都描述了自有游戏的结果核验。它们仅能证明相关能力已被公开提供，不能证明其全部资金、风险或体验机制。我们的推断是：不能把“可验证公平”当作独家卖点，更不能据此宣称比这些产品更受欢迎、更安全或更便宜。

护城河的建设顺序是产品口碑、可持续资本、可靠服务、有效分发关系与数据积累。当前这些都需要实践形成，不把代码开源或组件数量称为已建成护城河。

## 4. 价值交换与经营模型

玩家为娱乐承担投注风险和明确的交易／服务成本；LP 为已定义业务提供承保资本；推广方提供有效分发；协议运营维护产品、支付链路与服务。每一项收入必须对应来源，每一项资本承担必须对应可解释的补偿。

下一 casino 经济版本采用[内部经济设计](economic-design.md)定义的实际派彩扣减分配。规则保留 LP 份额，协议与推荐仅在剩余预算中形成债务；无有效推荐的未分配部分及舍入余数留在池内。这个方向已选择，分配比例要通过成本与资本模型校准。下一版本在新的 Bank／Router／Hub 发布单元中独立执行费用预算和 LP 留存下限；旧池义务继续履行，LP 自行选择是否迁移。主网现版本的实际条款继续以发布资料和合约为准。

经营分析同时回答：

- 玩家总支出是否与目标金额的娱乐体验相称，尤其 gas／VRF 固定成本的影响。
- LP 的费用留存与结果风险在资本占用后是否仍具参与吸引力。
- 协议可分配收入是否覆盖它实际承担的自动结算、基础设施、维护与支持。
- 渠道成本是否由真实留存贡献支持；返佣和获客支出不得重复漏算。

不设未经证明的固定 APY、回本期、市场份额或融资估值。内部模型情景不是公开预测。体育的收入分配、赔率质量和事件相关性另行建模，不把 casino 的派彩扣减公式当作体育默认合同。

## 6. 资源安排与下一工作包

采用两条主要实施线和一条支持线；工作单元指任务分工，不对外包装为真实团队规模。

| 工作线         | 当前优先交付                                               | 负责人职责                               | 结束或换挡条件                                 |
| -------------- | ---------------------------------------------------------- | ---------------------------------------- | ---------------------------------------------- |
| 产品与可靠结算 | 授权到投注恢复、完整回合体验、实际手机路径及收据           | 产品／前端实施；由独立审阅者验证结果     | 关键路径可完成、无未知提交自动重发、异常可恢复 |
| 经济与资本     | 下一经济模型校准、现 LP 指标纠偏、事件／历史归因、迁移方案 | 协议／数据实施；资金改动独立审阅         | 计量与模型一致，实际成本与压力情景有记录       |
| 材料与需求验证 | 两本白皮书、一份简介、玩家／LP／渠道阅读分流、研究方案     | 总负责人统筹，商业读者与技术读者分别审阅 | 外部读者能作出该材料预期支持的判断             |

体育保持规则、数据和独立风险设计推进；在初始 casino 使用和经营问题未解决前，不同时增加大范围体育市场和更多链。发现阻断支付或偿付的缺陷时，资金与恢复工作抢占上述排序。

后续具体工作包如下，先解决现有误导，再实现新承诺：

1. **WP：定位与材料。** 交付本总纲、商业主册、技术白皮书、简介及同步入口；通过按受众的独立审阅。本次执行此包。
2. **E1：现状指标纠偏。** 从 LP 经营页面移除或纠正把 GGR、资产级曲线、分页现金流当成完整 LP 收益的表达；补足当前可提现与新风险额度区分。此包不宣称建立新经济权益。
3. **E2：目标经济实现规格。** 校准费用分配、未分配预算、精度与成本情景；定义事件、预算校验和在途义务／迁移规则，再做资金逻辑实现。
4. **U1：玩家路径和内容。** 在 E2 不影响的范围完成首次／再次访问、授权衔接、错误恢复、手机路径、费用与收据说明；同步可观测指标。
5. **V1：有限范围需求与经营验证。** 先完成范围和指标定义，再收集用户任务与返访证据；资本与渠道放大取决于真实数据。
6. **S1：体育独立产品。** 沿用既有赛前单关范围，独立完成数据、赔率、规则、结果争议、资本和运行验收。

## 7. 假设登记与否决条件

| 假设                             | 要收集什么                                     | 结果不支持时如何处理                       |
| -------------------------------- | ---------------------------------------------- | ------------------------------------------ |
| 钱包熟练用户偏好本产品的组合体验 | 现有使用选择、首次任务观察、无补贴再次使用原因 | 改定位或主流程，不以增加奖励解释留存       |
| 目标投注金额能承受总成本         | 每局／批量的 gas、VRF 与等待分布，用户理解情况 | 调整金额范围、交互与费用设计；不先放大获客 |
| LP 补偿能吸引稳定承保            | 全分布与压力模型、资本占用、实际 LP 反馈       | 调整分配与风险上限；不许诺固定回报募集     |
| 渠道能带来真实使用者             | 来源明确的漏斗、补贴分组、重复使用与实际成本   | 收缩低质量来源，不以总流水掩盖亏空         |
| 体育与 casino 有交叉价值         | 分别访谈的使用场景、不同业务参与与成本         | 保留独立预算，调整投入顺序，不强推交叉销售 |

初步任务观察可发现摩擦，不能估计市场总体转化率。反馈记录要说明招募方式、样本范围、是否补贴及观察窗口。当前没有这类新用户研究结果，本稿不伪造访谈、意愿或客户承诺。

## 8. 能力、证据与对外可信度

已有工程与部署提供实现起点，具体范围查[发布日期事实表](../release/STATUS-v1.5.zh-CN.md)。这能证明某些能力存在，不能替代团队背景、经营资格、正式合作或商业成果证明。

对外合作尽调需逐项提供可核对的主体与联系人、服务范围、治理权限、技术与运行证据、支持责任和具体合作条件。未完成的项目直接说明进度，不虚构牌照、机构背书、付费用户、TVL、收入或团队履历。代码审查与合约源码验证按实际类别呈现。

实施与对外资料共同遵循一个原则：已经选择的方向要清楚，尚未取得的证据不能靠措辞补齐。现有版本状态、目标机制和市场验证结果保持分开，避免对外主张跑在产品之前。
