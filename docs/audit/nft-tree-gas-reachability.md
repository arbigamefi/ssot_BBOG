薄 prefix 和空 prefix 的提款是在后来资本已进入、全局 `L-K` 允许时执行的合法操作。
它们触发原树的全树回退。1,023/1,024 的薄 prefix 亏损样例，固定段已比 16/8 多约 25.3 万 gas。
24 小时冷却不改变这个分配路径；已成熟的旧 NFT 可以完成该历史。

历史长短不能单独决定 gas：256 的区间端点对齐，比 255 便宜；已发生的终结也会让 Bank 累计计数
和余额从零变为非零，降低后续部分 SSTORE 成本。因此“加几次历史交易”不必然比首次结算贵。

## 为什么历史 ID 的二进制结构会增加固定成本

树深度固定为 `D=40`，叶编号从 `F=2^40` 到 `2F-1`。销毁 NFT 不回收 ID。
设已使用的连续叶区间长度为 `N`，非空历史可分叉部分的高度不超过 `h=ceil(log2 N)`。

- `_push` 沿截点走一条完整路径，同时可能改写路径两侧的孩子。触发全树回退时还会走向最后已用叶。
- `_pushLazy` 对 prefix 每跨一个分叉，还会调用 `_getLeavesAmount` 递归计算被排除的 suffix。
  这些 suffix 遍历在多个高度重复，不能把整个调用理解成“只走 40 个节点”。
- 对高度 `d` 的 prefix 分叉，相应 suffix 递归最多访问 `2d-1` 个节点。
  把所有可能高度相加得到保守的结构计数 `sum(2d-1)=h²`；预检查函数也可能包含同类遍历。
  加上 `_push`、prefix 主路径与回退，总体结构工作量可达 `O(D+h²)`，而非只取决于当前 NFT 数量。

这只是递归形状的保守计数，不是经过逐 opcode 证明的 EVM gas 上界。
舍入、零金额分支、原始 packed 槽状态、是否已有账本和资产实现都会影响精确 gas。

## 40 层压缩见证，以及可以证明到哪一步

纯 vendor fixture 用 `forceNextNode` 构建四种结构；它没有声称执行过被跳过的历史。
其中只有 `LAST-1` 与 `LAST` 两叶有资金、随后给整棵树增加收益形成 lazy 状态时，
单次原树 `_removeLimit` / `_addLimit` 本体约为 **1.753m gas**。
每层都有非零 sibling 的另一结构反而约为 1.31m；“每个节点都有钱”也不是自动成立的最坏形状。

该两叶形状存在以下有限但极长的归纳构造：

1. 从空树开始创建一个 NFT，等满 24 小时，全部提出。root 和所有节点的 `amount` 恢复零，
   `nextNode` 增加一；已访问零节点仍保存非零 `updateId`。
2. 重复 `n=F-2=1,099,511,627,774` 次。然后正常存两次，编号正好为 `LAST-1` 与 `LAST`。
   若在第二次存款前开目标仓，截点固定为 `LAST-1`。
3. 第二次存款后，另一玩家开一个覆盖两叶的普通仓位并亏损给池子，形成一次跨两叶的盈利分配。
   root 更新，而孩子保留 lazy 金额。此后再结算目标仓。

仅前置铸造/全退就需要 `n` 次存款调用和 `n` 次提款调用；加两叶后共 `2^40` 次铸造。
串行复用同一笔本金的上述构造需要至少 `n` 天，约 **30.1 亿年**。
这不是允许大量本金和并行操作时的全局时间下界：并行 NFT 可以同时度过冷却。
一般情况下仍有至少一次 24 小时冷却和约 `2n` 次实际存取操作；若能持续执行的总操作速率为 `q/s`，
仅操作数量给出的时间下界就是 `(2n+2)/q` 秒。此处不假定现实网络能达到某个吞吐量。
这些是调用/事件次数，不是断言每个调用都必须占用独立交易。

计数器不会提前否定该归纳：存款使 updateId 加一，全退使其加二，因此前置历史后
`updateId=1+3n=3,298,534,883,323 < 2^64`。上述本金也可保持远低于当前资本准入上限。

实际完整历史与压缩 fixture 的原始存储不是逐字节相同：烧过的空节点有旧 updateId，
压缩 fixture 中未访问的空节点可能是全零槽。对这里的**特定终结路径**，可作较窄的等价分析：

- `_push`、suffix 查询和 `_isNeedUpdateWholeLeaves` 的该路径分支/金额计算依据 amount，二者相同。
- 零 amount 孩子不会被 `_push` 改写；`_pushLazy` 也不对其完整零子区间写入新增资金。
- 实际被写的节点都是已有资金路径或 root，两种构造中 packed 槽写前均非零；更新计数保持非零。
- 查询到但没有写的零 amount 节点，原始槽是否另有 updateId 不改变 cold SLOAD 单价。

这支持该路径的金额图、分支和被写槽类别的归纳等价；不扩张为所有 Solidity/EVM 状态完全等价的形式化证明。
实际执行的 4,096 和 16,384 次铸造/烧毁覆盖了相同模式较浅的历史，但没有执行 40 层的万亿次构造。

## 使用真实推荐引擎后，固定段仍超过 consumer 预算

`NftTreeGasSyntheticBankNineAwardsTest` 只压缩 Vault 的 `nextNode/updateId` 前置历史；
其后均使用该次绑定版本的 Bank/Vault/Router，并调用当时的 `DefaultReferralEngine.allocate` 生成奖励。
没有使用九个互不重合收款人的任意奖励数组冒充 Casino 情形。

参数为：base edge 200bps、effective edge 500bps，六段 skyline 各增 50bps；
L0/L1/L2 分配为 1000/2000/500bps，holdback 为 3000bps；玩家未达到解锁门槛。
**九笔奖励只有七个收款地址**：玩家、六层 skyline，L1/L2 与前两层 skyline 收款人重合。
付款使用 GameHub 相同的 fee-on-payout 公式，PF 与 XP 通过 Router 的 operator-share 上限。
制造 lazy 状态的另一玩家仓位也按普通 2x reserve、2% edge 和无推荐奖励的协议费结算。

独立冷测试的固定记账段约为：

- 最大 gross payout 分支：**2,842,187 gas**；
- 玩家输、池子盈利分支：**2,750,197 gas**。

另两个独立测试把整个 **2,447,746 gas** consumer 预算直接交给 Router 固定段，实际调用仍失败，
且 P/R/K、树、玩家现金与仓位状态保持原样。随后无限额诊断的会计正确性不代表预算内成功。
推荐引擎的计算发生在计时前，GameHub/VRFHub/游戏/真正 wrapper 和 USDC 代理成本也尚未加入。

因此，这个见证否定的是对该次绑定版本所作的“全部允许历史下，单纯调整游戏轮数即可保证同笔自动终结”的全称断言。

它不证明首发池目前存在这种状态，也不说明现实攻击者可以经济地制造万亿次存取。
