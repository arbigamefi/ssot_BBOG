## 结论与证据口径

不能用普通样例给全部游戏统一开放 100 轮，也不能把降低轮数当作任意树历史下的完整 gas 证明。
发布配置中的游戏轮数及 gas 仍须显式填写经过验收的值，不能直接采用测试夹具的 100 轮。

本轮将三件事分开验证：纯游戏计算、真实连续存款历史下的树与 Bank 记账、真实 wrapper/USDC
的完整受限回调。通过资金守恒或失败恢复测试，只证明对应断言；不表示回调在预算内成功。

## 唯一随机数来源

删除 GameHub 的 `betRandomData` 动态存储。VRFHub 是唯一持久化结果来源；GameHub 查询和终结
检查请求的 hub、仓位、Bank、付款人绑定。读取接口在 Received 和 Terminal 返回原始结果，
Awaiting/Cancelled 返回空数组；零 seed 是有效结果。终结必须仍是 Received。

GameHub 继续保存原有状态、结果 hash 和事件。整个 Hub 交付失败时，查询也能读到已收到的结果，
不再依赖两份存储同步。该改动保持同 seed 重试、终态原子性及 LP 未记账结果保护。

删除重复存储时的 64 项回归通过，相同独立冷交易夹具约减少 **85,146 gas**。
后续优化及其最终源码复跑如下；这个差值不是每个分支的恒定节省。

## 本轮等价优化

- Bank 将每个奖励收款人的两个 `uint64` 时间戳放入同一存储槽。奖励金额、释放算法、期限和
  公开 ABI 保持一致；没有收窄金额类型或合并不同收款人的债务。
- GameHub 在公开入口认证 canonical request 后，将已核对的 seed 传给同一结算实现，删除第二次
  相同请求读取。回调子入口仍只允许自身调用，外部调用者和 VRFHub 均不能通过该入口指定 seed。
  源 ABI 已重新导出，仅替换这个内部用途的外部入口签名，没有保留旧重载。

时间戳合并和请求去重阶段的核心定向回归 **144/144**、树历史 **38/38** 通过。新增奖励时钟回归包含 1,024 组 fuzz，
覆盖重复 payee、部分释放、重新奖励、到期和溢出回滚；随机数回归拒绝外部伪造 seed。
SDK **230/230** 及类型检查通过；普通命令中的 4 项 Anvil 测试仍是 skip，不计为本轮执行。

相同 `keno25-thin` 完整受限回调从 **2,220,506** 降至 **2,082,057 gas**，节省 **138,449 gas**。
两项优化没有改写 vendor 树、LP 权益或原子回滚边界，也没有解除 gas 发布准入。

## 每轮最低额与终态收据压缩

用户现确定 USDC **每轮最低 0.01、最多 25 轮**，25 轮最低总本金为 0.25；取消原单仓合计
1 USDC 门槛。Bank 的配置更名为 `minBetAmount`，GameHub 在资金移动与 VRF 请求前检查
`amountPerRoll`。SDK、页面、keeper、发布快照与部署模板同步使用该口径，不保留旧接口。

进一步把 GameHub 的内部终态收据压为两槽：四个金额以 checked `uint128` 保存；状态读取
已有仓位状态，手续费由 gross−net 计算。合法金额均受 Bank 的 `2^108−1` 资本边界约束，写入仍
使用 SafeCast，禁止截断。`getBetTerminal` 的外部返回类型、事件和资金规则保持一致。

同一份新下注规则代码的 8 个 25 轮固定历史回调，压缩前后都 **8/8 首次完成**；本组每例减少
**68,202 gas**，最高样例 Keno 从 **2,340,155** 降至 **2,271,953**。
这是一组真实 wrapper/USDC 本地 fork 的前后测量，不是所有状态恒定节省或完整历史上界。
源码清单、配置和逐例日志位于 `dist/per-round-minimum-2026-10-04/`。
本次最终合约单测与差分 **416/416** 通过，SDK/Web/keeper 定向 **224/224** 及三项类型检查通过。
包含每轮金额与 25 轮边界、未知/未终态收据、零赔付、部分退款、取整、回滚重试，以及真实
`2^108−1` 资本边界的大额结算/退款。未将浏览器、Anvil、PostgreSQL 或全部状态 gas 证明计入本轮。

固定 `callbackGasLimit` 下，代码节省不会自动等比例降低 wrapper 向玩家收取的 VRF 报价。
本轮保留报价额度，只有完整回调资格及余量确认后才可降低登记额度。未更换 provider，未部署。

## 测量边界

- 纯模块只有 `resolve` 的冷 STATICCALL 和固定返回复制，不含整个结算链。
- Bank/树测试只有 Router → Bank → Vault 与测试 token，不含 VRFHub、GameHub、真实 USDC 或模块。
- 完整 fork 从真实 wrapper 回调入口到受限 consumer，检查 Hub、Router、Bank/Vault 和 ack 终态；
  不包含 VRF proof 验证、coordinator 计费、服务可用性或延迟。
- 每个完整回调在独立 `setUp → test` 交易中测量。诊断重试不能冒充第一次受限回调成功。
- 同测试反复修改状态再调用会受到 EIP-2200 原槽/脏槽影响。单纯 `vm.cool` 不会修正这一点。
  纯模块测量还用回滚独立测量帧恢复访问列表，并断言同输入重复计费相同；不把热调用当冷调用。
- 合成高叶子编号的结构压力测试与实际执行连续存款历史明确区分。长历史的归纳可达性分析
  不等于在链上实际发生过，也不证明它是现实可行的攻击。

## Provider 预算

只读快照：Base Sepolia 区块 **47,657,524**，hash
`0x5a75e3c5fbaaa54dd1e67075af773668d43757b4e5de71f788ee69837650b872`。
wrapper `0x7a1BaC17Ccc5b313516C5E16fb24f7659aA5ebed` 的 overhead 为 13,400；
coordinator `0x5C210eF41CD1a72de73bF76eC39637bB0d3d7BEE` 上限为 2,500,000。

请求的 consumer gas `c` 必须满足：

```text
c + floor(c / 63) + 1 + 13,400 <= 2,500,000
```

因此最大 `c = 2,447,746`。内部还有嵌套调用的 EIP-150 限制与失败收尾预留；
一个不受限诊断调用消耗小于 `c`，也不保证相同输入在真实受限回调中能够完成。
发布前必须重新读取实际目标链配置。

## 树历史的固定成本

正常 API 执行的连续存款历史已显示，对齐的 16 笔旧存款 / 8 笔后入存款不是最坏场景。
部分或全部提空旧前缀会触发原树的范围回退；只数当前 NFT 数量也不足以描述成本，
叶子编号不会随 NFT 销毁而回收。

另有单列的合成长历史边界：跳过约 `2^40` 个历史编号，只留下末尾两笔真实存款，
再通过合法结算造成 lazy 状态。配合真实 DefaultReferralEngine 输出的九条奖励、七个收款地址，
优化后冷 Router → Bank → Vault 记账段测得盈利 **2,616,329**、最大 gross 分支 **2,708,271 gas**
（优化前分别为 2,750,197 / 2,842,187）。
这还不包括 GameHub、VRFHub、游戏计算和运行推荐引擎的成本，已经超过 consumer 上限。

该夹具压缩了历史计数，**不是实际执行了万亿次存款，也不是当前池子或现实攻击的证据**。
可达性的归纳构造、写槽类别及其局限见 [树历史说明](nft-tree-gas-reachability.md)。
它足以否定“当前实现只限制游戏轮数就覆盖任意完整树历史”的论证；不能据此宣称普通存款历史也需要该 gas，
也没有证明任何经济等价优化都不可能。原树生命周期是 `2^40` 个叶子编号，不是数学意义的无限历史。

分段测量进一步定位了成本：该合成 loss 场景的原树入口约 **1,753,630 gas**，其中首次展开约
372k、回退判定约 650k、分配约 724k；本例并未触发全树回退。Vault 树外成本约 40k，
其中包含必要的转账和现金覆盖校验，并非都可删除。只缓存几次余额读取不能填补当前缺口。
分段测量沿用同一次原调用中合法的暖槽，不把各阶段假装成分别冷调用；测量源和复现方法在
`dist/nft-callback-gas-2026-10-04/optimization/tree-profile/`，没有把临时插桩留进正式单元测试。

设计中已有的持久化 seed、原子回滚和公开重试必须保留。不能为方便通过测试而改写原树、
偷偷加入 NFT 总量限制，或把失败时改退款当成正常完成。完整生命周期的同笔成功保证尚未成立，
这一限制不能从发布验收中删除。

## 用户已裁决的验收边界

首发需要降低已知超预算配置的轮数，并继续覆盖游戏参数、seed、推荐奖励和存款历史；本轮样本不直接
成为发布默认值。用户此前要求所有允许状态都首次回调完成，随后提出先走简单的降低轮数路线。
因此停止扩展 provider 研究，保留当前 Chainlink 与原树，直接比较 25 与 50 轮。

在同一组通过真实存取 API 构造的历史下（1,023 笔旧存款全部退出、1,024 笔后入存款，
九条奖励、七个收款人，玩家拒付转应付款），8 个游戏各跑 25/50 轮的完整受限回调：

| 上限候选 | 本组首次完成 | 未首次完成                       |
| -------- | ------------ | -------------------------------- |
| 25 轮    | 8/8          | 无                               |
| 50 轮    | 6/8          | Keno、Plinko；原 seed 重试后完成 |

25 轮这组最高观测值为 Keno 的 **2,340,221 gas**。每个游戏采用固定 seed 和参数，不是随机数或
历史状态的穷举；50 轮失败样例的收尾耗气也不能当成成功结算所需的 gas。
结果支持优先选 **25 轮**，不支持 50 轮作为统一上限，也不证明任意树生命周期都能首次完成。
用户随后确定每轮最低 0.01 USDC、最多 25 轮，当前源码和部署模板已经按此修改；
未放宽此前任意历史首次完成的验收要求，未执行部署或开启发布。
逐例配置、结果、日志和一致的输入清单在
`dist/nft-callback-gas-2026-10-04/round-cap-comparison/`；输入清单 SHA-256 为
`91c26bdfda874d676ba958bb876ecb1dfda91e4313231b8b11dfacac1db0f71b`。
当前取舍见 [首次回调资格与轮数选择](../design/first-callback-settlement-qualification.md)。

既有 keeper 会监听未终结结果并重试；补结前该 Vault 的 LP 存取受已知结果保护。没有新增全池停注
开关，但尚未结算的准备金与仓位名额仍占用容量。“任何人可重试”也不等于无需有人提交交易。
