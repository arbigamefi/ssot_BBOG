## Disposition meaning and conclusion

- **FP**: the indicated defect is excluded by the stated source/state/authorization reasoning for the reviewed implementation. It is not a claim that all possible dependencies or future changes are safe.
- **ACK**: an intentional construct or bounded residual/configuration/operational concern is acknowledged. Source analysis does not discharge a deployment or workload condition called out in that row.
- **PENDING** would mean insufficient evidence to disposition the detector itself. No delivered detector requires this label after the scoped source review; the independent dynamic, target-network and capacity gaps below remain open regardless.

No new confirmed exploitable product defect was established from these 131 alerts. In particular, the three High alerts have explicit authorization/reentrancy explanations below; the 38 Medium alerts have individual sentinel, initialization, return-use or guard explanations. This is a scoped disposition, not a blanket statement that all state-changing functions are `nonReentrant`: `GameHub.onRandomWords` instead uses caller, request and state checks.

- Watcher errors were only logged. Initial subscription failures or a prolonged provider outage could leave WS delivery absent while HTTP scans continued. The runtime now owns one retry timer, closes old watchers/socket, and registers fresh subscriptions after errors or normal close. Watchers explicitly set `poll: false`.

The underlying viem API cannot abort an initial handshake before exposing its socket. A peer that never completes upgrade can still stall WS setup, while HTTP recovery and CLI shutdown remain available. There is no accumulation of parallel connection attempts.
