# Current audit scope

The project is prelaunch. The current candidate covers one Base Sepolia USDC casino pool;
Sports and outside LP funding require separate admission. Source identity is the committed
release revision and tree, not an earlier deployment's address or receipt.

## Build and scope

Solidity 0.8.37, Cancun, viaIR, optimizer 500. `foundry.toml` and `deps.lock` pin the same
compiler. Bank, SettlementRouter, PoolRegistry, GameHub, admitted modules, VRFHub/adapter,
referral accounting, SDK, keeper, indexer, website and release authentication are in scope.

The [constitution](../constitution/SSOT.v1.6.md), [executable invariants](../constitution/ExecutableSSOT.v1.6.md),
[asynchronous redemption](../adr/0034-async-lp-redemption-continuous-betting.md) and
[exit-only recovery](../adr/0035-recovery-rights-without-exit-blocking.md) define current behavior:

- Synchronous deposits acquire remaining active risk, including unresolved bets.
- LP requests and activation impose no betting pause. Only exiting risk/rights are segregated;
  staying capital returns to underwriting in the settlement transaction.
- Permanently unresolved positions do not block later batches. Their reserves remain backed,
  and recovery belongs to the recorded exiting controllers. Recovery has no guaranteed date.
- Liquid exits, player debt, fees, XP and historical backing are separate liabilities. Rounding
  never creates unbacked claims or transfers old exited rights to new LPs.
- Player transfer failure records player-only debt while terminalizing the position atomically.
- Guardian pause blocks new risk, deposits, activation and LP claims. Settlement, refunds,
  player-payable claims, cancellation and bookkeeping remain available.
- The USDC position minimum is 1 USDC; 100 rolls may each stake 0.01 USDC. Refund default is
  3,600 seconds, maximum 86,400 seconds. The active-risk book limit is 128 positions per pool.
- SDK admission uses active reserves and position capacity. Sports decimal odds must exceed 1.0.
- Website risk-in switches require explicit activation on each supported chain. Indexed GGR
  uses gross awards and starts each window's statistics at zero; it is not LP net profit.
- Release imports bind execution addresses, games, amount precision, ABIs and complete
  permissions to authenticated inputs. Amount precision comes only from signed LP decimals.
- Deployment writes the snapshot; one Python generator produces the verification helper.
  Verification uses Etherscan V2, `ETHERSCAN_V2_API_KEY` and the default compilation profile.

## Remaining admission work

1. Freeze the exact source/ABI/configuration identity and obtain external-auditor acceptance.
2. Deploy that identity, verify source and Safe configuration, authenticate the new signed
   release and matching web/keeper images, then run the [release checklist](../release/checklist.md).
3. Verify nonzero old-risk exits/recovery, signed cancellation, all gameplay boundaries,
   timeout refunds, refused-payment recovery, Safe pause/unpause, finalized/reorg replay,
   deployed-host WS reconnect/HTTP catch-up, process crash recovery and alert delivery.
4. Set the business peak and measure capacity cost, gas and tail latency. The owner has not
   selected a load target; local bounded loops do not establish a throughput SLA.
5. Decide module/Hub admission governance and guardian custody before outside LP funding.
   Sports requires its own terminal-path, timeout and capacity acceptance.

The [current Sepolia acceptance](../deploy/v16-sepolia-acceptance.md) identifies its deployed
source and completed receipts. It does not accept the current compiler's new bytecode. Local
validation is not external-auditor acceptance or completion of the native Codex Security scan.
