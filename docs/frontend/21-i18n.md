# Localization

The app supports five locales: English (`en`), Simplified Chinese (`zh-Hans`),
Brazilian Portuguese (`pt-BR`), Russian (`ru`), and Turkish (`tr`). The default is
English. Labels and accepted aliases live in the
[locale configuration](../../frontend/apps/web/src/i18n/config.ts).

[Request resolution](../../frontend/apps/web/src/i18n/request.ts) uses the
`arbi-locale` cookie first, then `Accept-Language`, then English. The
[language selector](../../frontend/apps/web/src/components/LocaleSwitcher.tsx)
writes that cookie and refreshes the current route. Routes have no locale prefix.

## Editing copy

Messages live in one `common.json` per locale under
[locales](../../frontend/apps/web/src/i18n/locales). English defines the key shape.
The [message loader](../../frontend/apps/web/src/i18n/messages.ts) merges translations
over English: missing or empty strings fall back to English, extra keys are ignored,
and nonempty translated arrays replace the complete English array.

Add keys to English first, then update the other four files. Preserve placeholders,
units, and financial meaning. Distinguish settlement amounts from wallet transfers,
and pending redemptions from claimable assets. Use the existing `next-intl`
translation hooks; keep addresses and encoded amounts out of translated prose.
Page metadata uses the [metadata helper](../../frontend/apps/web/src/i18n/metadata.ts).

Check changed screens in the supported languages, including long labels and mobile
layouts. The fallback prevents missing-key crashes; it does not certify translation
completeness. Run the existing locale and selector tests:

```bash
pnpm -C frontend/apps/web test -- src/i18n/config.test.ts src/components/LocaleSwitcher.test.tsx
```
