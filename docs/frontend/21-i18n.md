ArbiGameFi ships **i18n-ready from day one**. v1 supports English only, but
the infrastructure must allow adding any locale without code changes (only
translation files).

## 1. Library Choice

**`next-intl`** (Next.js 15 compatible).

Rejected alternatives:

- `react-intl` — not server-component-aware out of the box.
- `i18next` — runtime-heavier, weaker RSC integration.
- DIY context — fragile and unproven at scale.

## 2. Folder Layout

```
apps/web/src/
├── i18n/
│   ├── config.ts                 # locale list, default, fallback chain
│   ├── messages.server.ts        # server-side message loader
│   ├── messages.client.ts        # hydration handoff
│   └── locales/
│       ├── en/

│       │   ├── casino.json
│       │   ├── sportsbook.json
│       │   ├── portfolio.json

│       │   ├── ops.json
│       │   ├── legal.json
│       │   └── errors.json
│       ├── zh-Hans/    (future)
│       ├── ja/         (future)
│       └── es/         (future)
└── middleware.ts                 # locale negotiation
```

The shared `@ssot/ui` patterns do **not** ship translation files. They
receive copy as props (props sourced from app messages).

## 3. Routing

Subpath routing:

```
arbigamefi.com/        -> en (default, no subpath)
arbigamefi.com/zh/...  -> Simplified Chinese
arbigamefi.com/ja/...  -> Japanese
```

Detection order:

1. URL subpath.
2. Cookie `arbi-locale` (set when user explicitly switches).
3. `Accept-Language` header.
4. Default `en`.

Middleware redirects to the resolved locale if a user lands on a path
without a locale prefix and a non-default locale is preferred.

## 4. Message Keys

Naming convention: `<surface>.<noun>.<variant>`.

Examples:

```
casino.room.title
casino.room.cta.place
casino.room.cta.placing
casino.room.error.insufficientBalance
casino.empty.noBets
sportsbook.market.lockedBanner
portfolio.activity.column.amount
errors.WALLET_NOT_CONNECTED
```

Rules:

- camelCase for the leaf segment.
- No verbs in the key itself (`casino.room.cta.place`, not
  `casino.room.placeButtonLabel`).
- Mirror across locales — every key must exist in every locale (or fall
  back per §5).
- One message per concept. Reusable buttons share keys
  (`common.action.cancel`).

## 5. Fallback Chain

```
ja → en
zh-Hans → en
es → en
```

Any other unsupported locale falls back to `en`. CI fails if a key exists in
a non-default locale but not in `en`.

## 6. RTL Support

Infrastructure-ready, not active in v1.

- `<html dir="ltr">` default; switched to `rtl` only when a future RTL
  locale (Arabic, Hebrew) is added.
- Components must use logical CSS properties (`padding-inline-start`, not
  `padding-left`). Tailwind 3.4+ provides `ps-*`/`pe-*` utilities; use them
  throughout.
- Activating RTL requires a full visual audit + ADR.

## 7. ICU MessageFormat

We use ICU for plurals, gender, number formatting:

```json
{
  "casino.room.results.summary": "{count, plural, one {# bet} other {# bets}} settled.",
  "earn.deposit.preview": "You will receive {shares, number} LP shares of {bank}.",
  "common.amount.fmt": "{amount, number, ::.00#} {symbol}"
}
```

next-intl resolves these via `useTranslations` / `getTranslations`.

## 8. Number / Date / Currency Formatting

**Never inline.** Use `Intl.NumberFormat` and `Intl.DateTimeFormat` via
shared helpers in `@ssot/ui/utils`. Locale comes from `useLocale()`.

```ts
formatAmount(value, decimals, { locale });
formatRelativeTime(timestamp, { locale });
formatPercent(bps, { locale });
```

For UTC display (audit surfaces), always:

```ts
new Intl.DateTimeFormat(locale, { timeZone: 'UTC', ... })
```

No `toLocaleString` calls without a locale argument.

## 9. SEO Per Locale

- `<html lang="...">` per resolved locale.
- `<link rel="alternate" hreflang="..." href="...">` for every supported
  locale.
- Open Graph tags per locale where copy diverges.
- Sitemap includes per-locale URLs.

## 10. Server / Client Boundary

`next-intl` v3+ supports both RSC and Client Components:

- Server: `getTranslations(namespace)` in `page.tsx`.
- Client: `useTranslations(namespace)` in interactive components.

The provider mounts in `<AppShell>` so every subtree has access.

## 11. Switching Locales

A locale switcher lives in the nav drawer (`16-mobile.md §4.2`) and in the
footer. It:

- updates the URL subpath via `router.replace`.
- sets the `arbi-locale` cookie.
- preserves the route and query params.

## 12. Pseudo-locale

Development includes a `xx-pseudo` build that:

- replaces every translation with bracketed expanded text
  (`[!!Place bet --]`).
- expands strings by ~30% to surface layout breakage.
- highlights untranslated literals (any string not from messages renders
  unwrapped).

Available via `NEXT_INTL_LOCALE=xx-pseudo pnpm dev`.

## 13. Translation Workflow

1. Engineer adds a new key to the relevant `en/<namespace>.json` file
   with a comment header `// new-key-pending-translation`.
2. CI checks key consistency.
3. Translations are committed via PR or imported from translation vendor
   (Lokalise / Crowdin / Phrase — TBD).
4. Untranslated keys in non-default locales fall back to `en` at runtime.

## 14. Don'ts

- No inline JSX strings (`<button>Place bet</button>`) except in `/ops` with
  explicit `// i18n: deferred` comment.
- No hardcoded `Intl.NumberFormat('en-US', ...)`.
- No concatenation of translated parts (`t('hi') + ', ' + name`).
- No template-string interpolation that bypasses ICU placeholders.
- No locale-specific assets in the bundle. Locale-specific images
  (legal docs, regional warnings) load lazily.
- No `react-intl`. We use `next-intl`.

## 15. How To Enforce

```bash
# Inline string heuristic
node scripts/check-inline-strings.mjs

# Key consistency across locales
node scripts/check-i18n-keys.mjs

# Intl.* without locale argument
rg -nE "(toLocaleString|Intl\\.(NumberFormat|DateTimeFormat))\\(\\)" frontend/apps/web/src

# Banned alternative
rg -nE "from 'react-intl'" frontend
```

## 16. Glossary

| Term               | Meaning                                                                   |
| ------------------ | ------------------------------------------------------------------------- |
| ICU MessageFormat  | Standard for plurals/genders/format placeholders                          |
| Pseudo-locale      | A synthetic locale used to surface untranslated strings and layout issues |
| `hreflang`         | HTML attribute signaling localized alternatives to crawlers               |
| Logical properties | CSS `padding-inline-*`/`margin-inline-*` that respect writing direction   |
