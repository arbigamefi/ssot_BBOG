# Base mainnet v1.3 preflight audit — 2026-05-23

Status: **NO-GO for broadcast; casino-only contract preflight path repaired; frontend mainnet gate intentionally red**

## Scope

This audit checked the Base mainnet v1.3 pre-broadcast path:

- `docs/deploy/base-mainnet-v13-readiness.md`
- `docs/deploy/base-mainnet-v13.env.example`

No transaction was broadcast.

## Findings

### F1 — `chain-8453.json` must come from deployment artifacts

`frontend/packages/ssot/src/release/embedded/chain-8453.json` must be generated by
`pnpm -C frontend ssot:sync -- --from dist/ssot-release-chain-8453-<block>-<digest>.tar.gz`
after the Base mainnet release package exists. It must not be handwritten.

### F2 — Casino-first was documented but not executable

The readiness packet said a casino-only env should be used for casino-only launch review, but the
only public-network preflight path required a Sports pool and Sports role/cap values.

Repair in this audit:

- added `docs/deploy/base-mainnet-v13-casino.env.example`;
- added `make casino-mainnet-preflight-v13`;
- added `V13_REQUIRE_SPORTS_POOL=false` support to the shared preflight script;
- updated `docs/deploy/base-mainnet-v13-readiness.md` with the casino-only command path.

### F3 — Sports Phase 2 gate is a NO-GO packet validator

`make sports-phase2-gonogo-v13` exits successfully when the NO-GO packet is present and complete. The
green exit code means "the NO-GO controls are recorded", not "Sports public risk-in is approved".

Observed command:

```bash
make sports-phase2-gonogo-v13
```

Observed output included:

```text
decision: NO-GO
```

SportsHub public risk-in remains blocked unless an approved Phase 2 packet records GO and the linked
role custody, provider evidence, frontend access, bankroll caps, and ops coverage checks pass with
`REQUIRE_APPROVED=1`.

### F4 — Frontend mainnet readiness is machine-blocked until `chain-8453.json` exists

`make casino-mainnet-frontend-readiness-v13` now combines:

- `v13_casino_web_env_check.sh`;
- `pnpm -C frontend check:mainnet-release`;
- `pnpm -C frontend smoke:release-readonly -- --chain-id 8453`.

It must stay red until the signed Base mainnet release bundle has been generated and synced into
`frontend/packages/ssot/src/release/embedded/chain-8453.json`.

### F5 — Local release artifacts can be ignored by git

`deployments/` is ignored by default. A local `STRICT=1 make release-check` can therefore pass from
ignored local artifacts that a clean checkout or CI job does not have. Production release artifact
commits must explicitly force-add the required files with `git add -f`.

### F6 — Public risk-in needs one final no-broadcast GO gate

`make casino-mainnet-gonogo-v13` now bundles the final public-risk-in evidence checks:

- casino-only Base mainnet contract env preflight;
- approved `casino.frontend-access.v1` memo;
- production web env validation;
- embedded Base mainnet release check;
- read-only Base mainnet release smoke.

This gate must stay red until the real Base mainnet deployment artifacts are synced and the access
memo is approved.
