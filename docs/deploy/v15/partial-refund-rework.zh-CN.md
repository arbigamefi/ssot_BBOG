# v1.5 部分退款数据链路返工

## 缺陷与验收边界

`GameHub.getBetTerminal` 保存最终 `refundAmount`；`Bank.settleBet` 按 `payoutNet + refundAmount` 返还用户。但 `BetFinalized` 事件没有退款字段，当前读取链路漏掉提前停止批量投注后未使用的本金。现有证据是读取及统计错误，不是 Bank 漏付资金。

反例：原始投注 200000、中奖净派彩 196000、未使用投注退款 100000。总返还应为 296000，净收益应为 +96000；旧公共回执显示 -4000。八款游戏的单次投注验收不覆盖此分支。

字段保持独立：`payoutNet` 是中奖净派彩，`refundAmount` 是退回的未使用投注，不能混写。总返还为二者之和；净收益为总返还减原始投注。全额退款状态的派彩字段可能已表示退款，不能重复相加。未知退款不是零退款，不能用缺失字段生成精确盈亏。

## 实施与关闭顺序

1. **SDK 终态证明**：保留权威 getter 的退款字段及其与事件交易哈希的合并结果。仅有 BetFinalized 事件时保留未知状态。已实现；回归覆盖已知零、部分退款、字段缺失、getter 失败和日志 RPC 失败。
2. **keeper 与索引**：已为 keeper 实时事件、范围扫描、终态物化和离线回填增加权威退款读取，并核对事件的四项派彩金额与 getter 一致。读取或持久写入失败不推进扫描游标；原始事件重放不清空已确认退款。内存及 PostgreSQL 持久化验证通过。浏览器索引复用相同的终态校验，网络请求在 IndexedDB 事务外执行，失败时保留原游标。浏览器事实库按 v3 缓存版本、链 ID 和发布摘要隔离，从发布起点重建，保留旧数据库及交易日志。
3. **历史修复**：对 v1.5 finalized 且退款缺失的记录生成有前后值的 dry-run 清单，权威终态交叉校验后幂等回填。旧浏览器索引已改用按发布摘要隔离的新事实库重建；链上历史回填和公共回执字段补全仍待实施。公共回执不能仅凭 finalized 状态跳过字段补全。
4. **结果及统计**：统一房间结果、公共回执、分享、账户活动、赢家判定与聚合 SQL/内存实现的口径。区分原始投注额和扣除退款后的实际周转额。必要字段缺失时保持索引中。待实施。
5. **故障回归**：部分退款赢/输、全额退款、零退款、重复及乱序事件、RPC 失败、持久写失败、重启恢复；验证 Postgres 与内存结果一致。完整链路尚未通过。
6. **真实验收**：使用已批准的测试额度，模拟后执行小额两次批量 CoinToss，并通过 stopGain/stopLoss 提前停止。钱包余额、Bank 账本、链上终态、数据库、SDK 与 UI 必须一致；之后继续在途重启、写失败恢复、guardian 暂停与 Safe 恢复。

本文件第 1 步完成不代表退款缺陷关闭。第 2—5 步完成并部署验收镜像前，不推进真实部分退款 canary；完整 Sepolia 业务验收通过前不广播 Base 主网部署。

## keeper 配置边界

v1.5 持久索引验收必须启用 `KEEPER_SCAN_INDEX_EVENTS_ENABLED=true`。仅扫描 BetRandomReady 的精简模式不能补齐遗漏的最终金额；部署示例已开启完整扫描。终态 getter 不可用时保持失败及重试，不降级成零退款。此修改用于 v1.5 合约，不能将缺少 getter 的旧部署视为验收通过。
